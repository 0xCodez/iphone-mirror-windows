# Finish iPhone Mirror Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Call this private copy complete when the same gestures work on the cable and on Screen Mirroring, and a stranger can set it up from the repo without a new protocol.

**Architecture:** Keep the existing Qt window. Cable stays the USB HEVC picture in `iphone_mirror/usbvideo.py`. Screen Mirroring stays AirPlay in `iphone_mirror/video.py`. Screen Mirroring input stays the WebDriverAgent path already in `iphone_mirror/control/`. No second tunnel, no second app, no auto-updater.

**Tech Stack:** Python 3.11+, PySide6, pymobiledevice3, PyAV, the existing WebDriverAgent runner, Sideloadly for signing.

**Spec:** `docs/WINDOWS.md`

## Global Constraints

- Cable picture runs only while the phone is plugged in. Unplug stops it and must not switch to Wi-Fi.
- Screen Mirroring starts only when chosen, or from the Use Screen Mirroring button.
- Plugging in while Screen Mirroring is showing switches back to the cable picture.
- Left click is tap, double tap, or long press. Movement past 10 px sends nothing. Middle button drags both axes. Wheel is vertical and is not retuned.
- The bar lock persists across both pictures. Default is open.
- Close (X and Alt+F4) hides to the tray. Tray Quit exits.
- Do not raise the cable frame above the phone panel. Do not add a speaker picker. Cable sound cannot be decoded on Windows.
- Do not add a RemoteXPC or userspace tunnel. Do not patch pymobiledevice3 in site-packages.
- Do not commit `%LOCALAPPDATA%\iPhoneMirror\settings.json` or any AirPlay seed.
- The waiting line already uses the receiver name. Do not hardcode a computer name.
- WebDriverAgent has to be installed, signed, and running before Screen Mirroring clicks can work. A missing runner is a setup gap, not a new protocol.
- Do not relaunch the live window just to refresh docs. A behavior change needs a compile check first, then one attended check.

## Review Focus

- Screen Mirroring with the runner not started: the window stays usable, the lock stays open, and the copy does not tell the person to use the cable. Expected after the 12 Nov card removal. Not retested in the running process, which still has the old card until the next launch.
- Unplug during a cable picture: the picture stops, and the phone camera and mic are free. The stop is built. The camera release after a dead USB tunnel is not retested.
- Plug in during Screen Mirroring: the window returns to the cable picture without a second launch.
- Wheel on Screen Mirroring: same stutter as the cable. A smoother wheel is out of scope.
- Error and decrypt-error screens: Try again, the other picture, and Open log are in the copy. Nobody has walked them.
